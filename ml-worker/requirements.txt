# Elasticsearch client. 8.19.3, not the newer 9.4.1: the client enforces
# Elastic's N/N-1 major-version compatibility policy at the protocol level
# (an Accept header naming its own major version), and the server this
# talks to is pinned to 8.13.4 across the rest of the repo
# (docker-compose.yml's elasticsearch service). A 9.x client sends
# `compatible-with=9`, which the 8.13.4 server rejects outright with
# media_type_header_exception -- confirmed live against a disposable 8.13.4
# container, not just read from a compatibility table. See #62.
#
# #593: a Dependabot PR (build(deps): bump elasticsearch from 8.19.3 to
# 9.4.1) bumped this to 9.4.1 anyway, directly contradicting this comment.
# Reproduced live: es.ping() -> HEAD / returns HTTP 400 against the actual
# running 8.13.4 server, exactly the media_type_header_exception this
# comment already describes. Reverted to 8.19.3.
